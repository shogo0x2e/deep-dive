# KinectでMainを走る

統合ブランチ: `codex/kinect-highway-integration`。プロジェクトは `highway-surfing`、シーンは `Assets/Scenes/Main.unity` です。
`Assets/Scenes/Sandbox/KinectDebug.unity` は骨格・配置の比較用に残しています。

## 今回の45°条件で試す

1. Kinectは前の測定と同じく画面側に固定します。Mainの初期設定は **SENSOR: SCREEN 0 DEG** です。「45°」は、横向きから時計回りに参加者の体を約45°回した条件です。Kinect本体を45°の位置に移動した条件とは異なります。
2. 他のKinect ViewerやSandbox側の取得を停止し、MainをPlayします。Kinect取得とSpout出力が自動で始まります。
3. 他の人よりKinectの手前で、全身が見える位置に立ちます。前の試行では腰の奥行き約1.4〜1.6mで取得できました。
4. 画面の案内に合わせて、両腕を肩の高さで体の前後へ伸ばし、左右に傾けずサーフィン姿勢を約2〜3秒保ちます。
5. ポーズを検出すると本人のIDを固定し、その姿勢を中央として自動登録します。進捗が満ちると案内が消え、自動前進を始めます。参加者がボタンやキーを押す必要はありません。
6. 画面の左へ体を傾けると左へ、右へ傾けると右へ移動します。中央へ戻すと横移動が止まります。

腕は頭上ではなく肩の高さに伸ばします。ポーズ検出を0.65秒継続した後、1.5秒以上・8サンプル以上の安定した胸と腰で中央を登録します。登録中に腕を下ろしたり、骨格が消えたり、体が大きく動いた場合は登録をやり直します。ポーズを保てば自動で再試行します。

## 参加者の入れ替わり

開始前は、腰の信頼度が十分な人のうち、センサーからの奥行きが最も小さい人を選びます。ポーズを保った人のIDを固定してから中央登録に入ります。

走行中は別の人へ入力を乗り換えません。胸腰の信頼度不足や古い結果の間は横方向入力・横移動を即座に0にします。登録済みなら道路の前進は続き、同じIDが戻れば操舵が戻ります。

固定した人が約3秒見えなくなると、中央・ID・走行位置を解除し、案内に戻ります。次に手前へ来た人がポーズを取ると、新しい中央を自動登録して走れます。SDKがIDを再発行した場合もこの流れで入り直せます。単に胸のconfidenceが落ちただけで本人の骨格結果が届いている場合は、退出と判断しません。

## 運営者向けの調整

Hで操作パネルを表示できます。通常は非表示で、OBSへは送られません。

| 操作 | 動作 |
|---|---|
| C / REGISTER NEUTRAL | 中央を解除し、もう一度ポーズを待つ。参加者の通常フローでは不要 |
| SPACE / PAUSE | 前進と横移動を一時停止・再開 |
| R / RESET RIDE | 開始位置へ戻る。中央登録は維持 |
| W / S | 前進速度を調整 |
| SENS − / SENS + | 操舵感度を調整。初期値x1.0 |
| FLIP LEFT / RIGHT | 左右反転。設置確認用 |
| RESELECT | 固定IDと中央を解除し、手前の人のポーズを待つ |
| SCREEN 0 / LEFT 45 / RIGHT 45 | 実機の位置に合わせて座標変換を変更。体の向きではない |
| STOP / START KINECT | 実機取得を停止・再開 |
| K / KEYBOARD PREVIEW | Kinectを止め、A/Dのキーボード操作へ。CかSTART KINECTで戻る |

`KinectSurfing` のInspectorで感度、ポーズ検出時間、退出待機時間、実機の自動起動を調整できます。`KinectDebugRig` のDead Zone Degrees（初期3°）、Full Scale Degrees（初期18°）、Smoothing Seconds（初期0.08秒）も調整可能です。

`SensorOrigin_EDIT_POSITION_AND_ROTATION` は実機の位置・向きに合わせる親Transformです。初期距離2m・高さ1.1mは仮値です。画面軸は独立した `ScreenReference_FixedAxes` にあり、ゲーム内カメラの進行・旋回には影響されません。Kinect本体を左右斜めへ移動したときだけ、その側の45°設定に変更します。

## OBSと案内画面

Main Cameraは **HighwaySurfing.Main / 1920×1080** をSpoutへ送ります。OBSのSpout2 Captureでこの送信元を選びます。開始案内は投影映像に含み、操作パネル・骨格のデバッグ表示は含みません。

案内はアニメーション付きのサーフィン姿勢図、日本語メッセージ、登録進捗で構成しています。参加者向けの押すボタンはありません。案内中は可読性のためカメラのポストプロセスを一時停止し、案内が消えると夜景のBloom等を復帰します。日本語は同梱のNoto Sans CJK JPから生成した静的TMPフォントを使用しています。

## 確認済みの範囲（2026-10-30）

- Mainで実Kinect取得・約15fpsの結果到着を確認。以前の45°試行の記録は `KinectDebug.md` に記載。
- ポーズ検出9件、座標変換・中央登録・追跡断13件、手前の人物選択14件のチェックが通過。
- 明示的な検証用合成骨格で、自動登録→案内非表示→前進、±12°から入力±0.60の左右移動、追跡断時の即時横停止、3秒退出で案内と中央をリセット、再入場時の自動登録を確認。
- ネイティブSpoutReceiverで1920×1080の案内画像と走行映像を受信。実際のOBS・プロジェクターと、実機での自動ポーズ認識の使い心地は現場で確認する対象。

合成骨格は試験時にだけ明示的に許可し、通常のPlayでは無効です。Kinectが切れても合成骨格やキーボードへ自動で切り替わりません。この版はEditorで操作感を試すためのPoCで、Standalone配布用SDK配置は未検証です。
