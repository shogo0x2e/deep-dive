# KinectでMainを走る

元の統合版は `codex/kinect-highway-integration`（`a2efb4b`）に保存しています。腕による速度操作は現在の `main`（実装コミット `3d3385e`）にあります。プロジェクトは `highway-surfing`、シーンは `Assets/Scenes/Main.unity` です。
`Assets/Scenes/Sandbox/KinectDebug.unity` は骨格・配置の比較用に残しています。

## 今回の45°条件で試す

1. Kinectは前の測定と同じく画面側に固定します。Mainの初期設定は **SENSOR: SCREEN 0 DEG** です。「45°」は、横向きから時計回りに参加者の体を約45°回した条件です。Kinect本体を45°の位置に移動した条件とは異なります。
2. 他のKinect ViewerやSandbox側の取得を停止し、MainをPlayします。Kinect取得とSpout出力が自動で始まります。
3. 他の人よりKinectの手前で、全身が見える位置に立ちます。前の試行では腰の奥行き約1.4〜1.6mで取得できました。
4. 画面の案内に合わせて、両腕を肩の高さで体の前後へ伸ばし、左右に傾けずサーフィン姿勢を約2〜3秒保ちます。
5. ポーズを検出すると本人のIDを固定し、その姿勢を中央として自動登録します。進捗が満ちると案内が消え、自動前進を始めます。参加者がボタンやキーを押す必要はありません。
6. 画面の左へ体を傾けると左へ、右へ傾けると右へ移動します。中央へ戻すと横移動が止まります。

腕は頭上ではなく肩の高さに伸ばします。ポーズ検出を0.65秒継続した後、1.5秒以上・8サンプル以上の安定した胸と腰で中央を登録します。登録中に腕を下ろしたり、骨格が消えたり、体が大きく動いた場合は登録をやり直します。ポーズを保てば自動で再試行します。

開始案内は実際の骨格に応じて「腕を上げてください」「もっと高くしてください」「もうちょっと高くしてください」「もうちょっと低くしてください」「腕を下げてください」と変わります。片腕だけの修正なら画面側／後ろ側の腕を示します。高さが合っていても腕が曲がっている場合はひじを伸ばす案内、体が傾いている場合はまっすぐ立つ案内になります。追跡できていない腕に高さの指示は出しません。修正案内の切替に0.25秒の確認時間を設け、細かな揺れによるちらつきを抑えています。

## 参加者の入れ替わり

開始前は、腰の信頼度が十分な人のうち、センサーからの奥行きが最も小さい人を選びます。ポーズを保った人のIDを固定してから中央登録に入ります。

走行中は別の人へ入力を乗り換えません。胸腰の信頼度不足や古い結果の間は横方向入力・横移動を即座に0にします。登録済みなら道路の前進は続き、同じIDが戻れば操舵が戻ります。

固定した人が約3秒見えなくなると、中央・ID・走行位置を解除し、案内に戻ります。次に手前へ来た人がポーズを取ると、新しい中央を自動登録して走れます。SDKがIDを再発行した場合もこの流れで入り直せます。短時間のconfidence低下では退出扱いにせず、次の姿勢確認の待機時間を設けています。

走行中に腕を下ろしたり閉じたりした姿勢が約1.5秒続いた場合も、中央・ID・走行位置を解除して開始案内に戻ります。腕や姿勢を判定できない状態が続いた場合は約3秒待ちます。走行中の判定は、開始時の厳密なTポーズとは分けており、操舵やアクセル／ブレーキで腕を上下する動きは走行姿勢として許容します。`KinectHighwayInput.PoseReleaseSeconds`で姿勢終了までの待機時間を変更できます。

## 腕によるアクセル／ブレーキ（試作）

初速は従来と同じ138 km/hです。開始時のTポーズで画面側の腕と、その腕の水平に近い角度を自動登録します。左右どちらの手が前でも、画面に向かう側を選び、走行中は切り替えません。

- 画面側の腕を上げる: ブレーキ。後ろ足に荷重をかける動作の代わりです。
- 画面側の腕を下げる: アクセル。前足に荷重をかける動作の代わりです。
- 開始時の腕の傾きから±8°以内: 加減速なし。その時点の速度を維持します。

しきい値を超えた間だけ速度を変え、28°で最大入力になります。最大加速度は30 km/h毎秒、最大減速度は60 km/h毎秒。速度の範囲は0〜220 km/hで、ブレーキを保つと停止し、アクセルで再出発できます。新しい参加者の登録時は138 km/hに戻ります。

左右操舵のための体の傾きを腕の角度から差し引き、操舵だけで加減速しにくくしています。腕を真下に下ろした、折りたたんだ、骨格が古い／取得できない場合は加減速を止めます。体重や足の荷重そのものは測っていません。

`KinectSurfing` の **Kinect Arm Speed Input** で `Threshold Degrees`、`Full Scale Degrees`、加減速度を調整できます。`Enable Arm Speed`をOFFにすると従来の一定速度操作になります。Hの運営パネルで速度、ACCEL/BRAKE/CRUISE、腕の角度、選択した手（L/R）を確認できます。

## 道路拡張・衝突減速版（2026-10-30）

`codex/highway-playtest` ブランチに、連続した分岐ランプと左側合流、立体車体、衝突演出、低音、衝突時の減速を追加しています。取り込み手順とMac試遊は [HighwayKeyboard.md](HighwayKeyboard.md) を参照してください。

Mainの `NightHighway` → **Night Highway World > Collision Gameplay** で `Collision Slowdown Enabled` をON/OFFできます。初期値はON、`Collision Speed Loss Percent` は30（138 → 96.6 km/h）。OFFにしても衝突の画面効果と音は残ります。減速後は腕のアクセル操作で再加速でき、Rや参加者の再登録では開始速度へ戻ります。Play中に切り替えられますが、設定を保持するときは停止後に変更してシーンを保存します。

2026-10-31の衝突音修正では、鈍い低音を強め、衝突時だけ駆動音・通過音を短く下げます。`NightHighway` → **Highway Impact Feedback** の `Impact Volume` は初期0.85、`Duck Ride Sound` で一時的な走行音の減衰をON/OFFできます。

今回の追加分はMac・Kinectなしで検証しています。Windowsの実機KinectとSpoutは会場で確認してください。

## 運営者向けの調整

Hで操作パネルを表示できます。通常は非表示で、OBSへは送られません。

| 操作 | 動作 |
|---|---|
| C / REGISTER NEUTRAL | 中央を解除し、もう一度ポーズを待つ。参加者の通常フローでは不要 |
| SPACE / PAUSE | 前進と横移動を一時停止・再開 |
| R / RESET RIDE | 開始位置へ戻る。中央登録は維持 |
| W / S | 前進速度を調整 |
| SENS − / SENS + | 操舵感度を調整。初期値x1.0 |
| FLIP LEFT / RIGHT | 左右反転。設置確認用 |
| RESELECT | 固定IDと中央を解除し、手前の人のポーズを待つ |
| SCREEN 0 / LEFT 45 / RIGHT 45 | 実機の位置に合わせて座標変換を変更。体の向きではない |
| STOP / START KINECT | 実機取得を停止・再開 |
| K / KEYBOARD PREVIEW | Kinectを止め、A/Dのキーボード操作へ。CかSTART KINECTで戻る |

`KinectSurfing` のInspectorで感度、ポーズ検出時間、退出待機時間、実機の自動起動を調整できます。`KinectDebugRig` のDead Zone Degrees（初期3°）、Full Scale Degrees（初期18°）、Smoothing Seconds（初期0.08秒）も調整可能です。

`SensorOrigin_EDIT_POSITION_AND_ROTATION` は実機の位置・向きに合わせる親Transformです。初期距離2m・高さ1.1mは仮値です。画面軸は独立した `ScreenReference_FixedAxes` にあり、ゲーム内カメラの進行・旋回には影響されません。Kinect本体を左右斜めへ移動したときだけ、その側の45°設定に変更します。

## OBSと案内画面

Main Cameraは **HighwaySurfing.Main / 1920×1080** をSpoutへ送ります。OBSのSpout2 Captureでこの送信元を選びます。開始案内は投影映像に含み、操作パネル・骨格のデバッグ表示は含みません。

案内はアニメーション付きのサーフィン姿勢図、日本語メッセージ、登録進捗で構成しています。参加者向けの押すボタンはありません。案内中は可読性のためカメラのポストプロセスを一時停止し、案内が消えると夜景のBloom等を復帰します。日本語は同梱のNoto Sans CJK JPから生成した静的TMPフォントを使用しています。

## 走行音と光の演出

Tポーズの登録完了時に短い上昇音と淡いミント色の発光が入り、ボードの電動モーターをイメージしたなめらかな駆動音が立ち上がります。常時鳴る風ノイズはありません。駆動音の音量・音程、道路わきの光の長さは実際の速度に連動し、アクセル中は駆動音が少し強まります。腕を水平へ戻して速度を維持した間は、その速度に応じた駆動音を保ち、ブレーキで弱まります。停止時は駆動音が消えます。

短い風切り音は、実際の街灯や車との通過位置に合わせて鳴ります。街灯は短く控えめに、車は近さと相対速度に合わせて強さ・音程を変え、通る側へステレオ定位します。対向車や後方から抜いていく車も対象です。停止中も走行登録が続いていれば、そばを通る車の音は鳴ります。車の描画と音は同じ位置計算を使い、加減速で車が瞬間移動しないよう移動距離を積算しています。再登録・位置リセット・交通の遠方への折り返しで、架空の通過音は鳴らしません。

185 km/hを超えると画面周辺に集中線が徐々に現れ、220 km/hで最大になります。中央の進路は空けています。既存の速度連動FOVは変更していません。案内への復帰・一時停止では走行音と追加エフェクトがフェードアウトします。一時停止の解除や短時間の追跡断では出発音を繰り返さず、新しい登録成立時にもう一度鳴らします。

`NightHighway` の **Highway Ride Feedback** で調整できます。

| 設定 | 初期値 / 用途 |
|---|---|
| Master Volume | 0.7。走行音・出発音の音量 |
| Motor Volume | 0.8。モーター音の音量 |
| Pass By Volume | 0.7。街灯・車の通過音の音量 |
| Sound Enabled | 音のON/OFF |
| Effects Enabled | 追加した光のON/OFF |
| Road Light Intensity | 1。道路わきの光の強さ |
| Speed Line Intensity | 1。高速時の集中線の強さ |
| Speed Line Threshold Kmh | 185。集中線が出始める速度 |

現在のMainは、無料・CC0のTesla Model S Plaid実録音から作った低・中・高速の3ループと、W3「Car Passing」由来の通過音を使います。速度70 / 138 / 220 km/hを音色の基準にし、段差なくクロスフェードします。速度維持では音程も維持し、アクセル開度で音量と明るさが増え、ブレーキでは駆動音が弱まります。操作の速度しきい値は変更していません。

音源は `Assets/Audio/Highway/Recorded`。車の通過音は2.9秒、街灯用の短い切り出しは0.57秒で、それぞれ音量ピークを通過位置へ合わせます。8音まで重ねて再生でき、常時鳴る風ノイズはありません。録音の左右移動はモノラル化し、実際の車・街灯の側へ定位させます。元録音のドップラー変化を二重に加工しません。

録音素材の出典・加工内容・再生成手順は [AudioSources.md](AudioSources.md) にあります。今回は公開HQ MP3を加工した試作で、原本のロスレスWAVではありません。有料候補M2は使っていません。約1.15秒の出発音は従来の合成音です。録音版のMainへの設定は `Tools > Highway Surfing > Use Recorded Ride Audio`（保存済みMain、Play停止中）。旧 `Install Ride Sound and Light` は合成音を再生成するメニューです。BGMは追加していません。

光と集中線はMain Cameraで描画され、Spoutにも含まれます。**Spoutは映像のみ**です。OBSへ音も入れる場合は、[OBSのアプリケーション音声キャプチャ](https://obsproject.com/kb/application-audio-capture-guide)でUnity Editor（ビルド版では実行アプリ）を別途指定します。同じ音をデスクトップ音声でも重複して拾わないようにします。

## 確認済みの範囲（2026-10-30）

- Mainで実Kinect取得・約15fpsの結果到着を確認。以前の45°試行の記録は `KinectDebug.md` に記載。
- ポーズ検出9件、座標変換・中央登録・追跡断13件、手前の人物選択14件のチェックが通過。
- 腕の速度操作は28件の幾何・しきい値チェックが通過。Mainの合成骨格で、操舵と同時に5°では138 km/hを維持、20°上げると減速、下げると加速、水平に戻した後の速度一定、腕confidence喪失時の加減速停止を確認。
- 高さ別案内と走行姿勢は39件のチェックが通過。Mainで上下の修正案内と文字の収まりを確認。合成骨格で強いブレーキ＋操舵では案内が出ず、腕を下ろすと約1.5秒で案内に戻り、再びTポーズを取ると中央・腕を再登録して138 km/hで出発することを確認。
- 明示的な検証用合成骨格で、自動登録→案内非表示→前進、±12°から入力±0.60の左右移動、追跡断時の即時横停止、3秒退出で案内と中央をリセット、再入場時の自動登録を確認。
- ネイティブSpoutReceiverで1920×1080の案内画像と走行映像を受信。実際のOBS・プロジェクターと、実機での自動ポーズ認識の使い心地は現場で確認する対象。
- 音・光はMainの合成骨格で、138→220 km/hへの加速、220の維持、約47までの減速、低速維持、停止、一時停止、案内復帰、再登録を確認。通常速度では集中線なし、最高速では最大、案内中は消失。再登録時だけ出発音が再発火し、一時停止解除では発火しないことを確認。
- UnityのAudioListener出力を連続計測し、走行中の非ゼロ波形とフェードを確認。Spout受信画像で通常・高速・案内・発光を確認。スピーカーやOBSでの実際の音量・聴こえ方は現場で調整する対象。
- モーター＋通過音への差し替え後も上記の速度・案内シーケンスを再検証。街灯と車の通過音を確認し、一時停止・案内中は新しい通過音が発火せず、案内待機中の音声出力はゼロ。検証時の最大出力ピークは約0.211でクリッピングなし。18台の車すべてで、その場で速度値を変更しても描画位置が飛ばないことを確認。
- 無料実録音の3段階ループ＋W3版も同シーケンスで再検証。138→220→約47 km/h、水平時の速度維持、ブレーキ時の駆動音低下、停止・一時停止・案内でのフェード、再登録時の出発音を確認。0〜220の全221速度でブレンド音量と基準音程の整合を確認。24秒の試験で最大出力ピーク約0.227、最大同時通過音4、Unityエラー・警告0。記録はローカルの `.Local/Review/RecordedAudioTrial.csv`。実際の音色は試遊で評価する対象です。

合成骨格は試験時にだけ明示的に許可し、通常のPlayでは無効です。Kinectが切れても合成骨格やキーボードへ自動で切り替わりません。この版はEditorで操作感を試すためのPoCで、Standalone配布用SDK配置は未検証です。
